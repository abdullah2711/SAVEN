Required corrections:

1. **HIGH — invalid credentials can authenticate through dummy-input substitution.** `src/auth/password-policy.mjs:100–105,222–242`: empty, non-string, oversized or NUL-containing input becomes the fixed DUMMY_INPUT, but verification still checks that replacement against the real stored verifier and can return `valid: true`. For an active account whose current Argon2id password is the public string `saven-bounded-dummy-verification-input`, the route's missing/non-string password becomes empty, is replaced, and can issue a session. The fixed string meets the new-password policy. This is a source-derived counterexample; reviewer did not execute it. Keep input validity as a separate flag, run bounded admitted dummy work for invalid input, and unconditionally return invalid regardless of any derived match. Do not ban the dummy string as a workaround. Add adapter and real-route regression tests with a verifier deliberately created from that exact string: missing, null, numeric, empty, oversize and NUL inputs must never authenticate, rehash or issue a cookie/session; the actual valid string must still work. Include retained-scrypt verification results in the adapter checks.

2. **HIGH — exceptional accounting is not serialized with admission, and audit failure does not stop later unaccounted work.** `routes.mjs:335–359` and the reset equivalent invoke `durableExceptional` only after `limiter.attempt` has rolled back and released its transaction-scoped locks. Pause that autocommit write: a waiting attempt can acquire the same scope, see no failure and start another KDF. At limit 1, multiple exceptional attempts can therefore enter before any budget row commits. A process exit between rollback and the independent write permanently loses the attempt. Merely reacquiring the lock to append a later row does not close the unreserved interval. When `AuditWriteError` occurs, the handler simply returns 503; subsequent requests still enter verification with the unchanged budget. The new single-request audit-down test establishes no cookie, not fail-closed KDF admission over repeated requests. Preserve a durable reservation/accounting decision before releasing scope serialization or doing work that can leave no record; use an explicit transaction/savepoint or separately committed reservation design with defined recovery semantics, within TOUCH or return for a narrowly revised contract if additional storage is necessary. Keep successful credential upgrade/session/success-audit atomic. Test paused exceptional logging with concurrent same-scope requests, a failure boundary between rollback and logging, repeated audit-store failures, and recovery. Assert the allowed number of KDF starts as well as response/session/audit outcomes. Do not claim that an uncertain COMMIT proves no session exists: withhold credentials and document ambiguity; the retained store can report uncertainty after a real commit.

3. **MEDIUM — the rate identity still consumes unsanitized request headers.** Login `routes.mjs:248–250` and forgot-password compute sanitized `ingress`, then pass the original request/header to `limiter.keysFor`. `throttleScopes` hashes any nonempty raw configured-header value. An invalid configured IP therefore still creates a network scope, contrary to README/report claims that it is discarded for scope, session and audit; equivalent valid IP spellings are not normalized either. Audit/session sanitation is a real improvement, but it is not the shared trusted-boundary identity. Feed one validated, canonical ingress identity to every consumer, including both limiter endpoints; default-off headers must remain ignored. Add direct scope assertions for invalid configured headers and canonical equivalents, plus account/network budget checks for login/reset. Preserve the documented requirement that the ingress itself prevents client forgery before enabling a header in deployment.
