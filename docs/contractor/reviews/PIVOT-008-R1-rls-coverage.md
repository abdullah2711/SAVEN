## Required corrections

1. **HIGH — enforce the installed contract, not names alone.** `required_relations` includes an object_type, but `MISSING_REQUIRED_RELATION` only tests `to_regclass(...) IS NULL`; required sequences use the same existence-only test. A view or sequence occupying a required tenant-table name is no longer a tenant table and can evade the table/RLS obligation while satisfying the manifest's existence check. Also the revision contains no validation of the required applied migration ledger versions/checksums despite that requirement in finding 1. Enforce the reviewed relkind/signature/profile and prerequisite immutable installation bindings. Add CLI negatives for an incompatible object at an expected name and missing/conflicting installation binding, with compatible installed controls. Do not rewrite accepted migration bytes or silently register missing bindings.

2. **HIGH — make weakened policies fail the actual gate.** `policy_judged` treats a predicate as bound if its text mentions tenant_id/current_tenant_id, and an admission predicate if it mentions session_admitted. It does not require their accepted relationship. R1's own test demonstrates the problem: `tenant_id = tenant_id AND tenant_data.current_tenant_id() IS NOT NULL`, with the matching admission call added, permits foreign rows. The test asserts `leaked === 1`, restores the guards and finally asserts empty coverage. It does not assert that the CLI refuses that unsafe target or run a normal no-leak assertion which goes red under the mutation. `--database` only runs the catalog query/protocol probes; the separate behavioral fixture is not an inspection of that target. Thus a new healthy fixture and six passing self-tests do not certify the weakened installed database.

   No arbitrary SQL theorem prover is required: validate the reviewed canonical policy expressions/roles/commands and explicitly reviewed variants, or fail closed on an unrecognized contract. Alternatively supply an equally strong read-only target verification design within scope. Require the existing nonliteral weakening to make the actual CLI nonzero with an exact diagnostic, and preserve a reusable no-foreign-row behavioral assertion that fails under that mutation and passes after restoration. Preserve current own-tenant positive controls. Policies applicable only to the wrong role must not fill the operation matrix merely because they exist; enforce actual role applicability. Do not describe an expected-leak demonstration as the required red/green guard-removal proof.

3. **HIGH — restore and complete effective authority coverage.** The R1 query has no schema ACL or has_schema_privilege check; the initial gate's `RUNTIME_SCHEMA_CREATE` protection disappeared. Granting CREATE on tenant_data/auth/operator to a runtime role or its login need not produce a violation in the new query. Add effective schema ownership/USAGE/CREATE profile checks, including PUBLIC and indirect authority, and regression cases preserving this earlier control.

   `login_membership` explicitly filters `WHERE r.rolcanlogin AND NOT r.rolsuper`. Therefore `LOGIN_ROLE_ATTRIBUTE` cannot discover a superuser runtime login: it disappeared before classification. `UNKNOWN_PRIVILEGED_PRINCIPAL` also excludes superusers. Associate runtime login membership before rejecting unsafe attributes; do not reject unrelated offline superusers merely for existing. Test a deliberately elevated associated login and an unrelated administrator control. Check dangerous role-switch targets by their capabilities, not only membership in required owner classes.

   `covered_functions` now includes only tenant_data/auth/operator schemas. The original query also included functions owned by SAVEN principals outside those schemas. A public-schema definer owned by a constrained SAVEN owner, with a runtime execution grant, can disappear from all function ACL/owner checks. Restore authority/dependency-based function coverage outside the three schemas and test the external-schema path. Keep column ACL and wrong-service EXECUTE corrections; no broader grant is authorized.

4. **HIGH — evaluate authority along the whole path and for reachable writes.** `UNSAFE_VIEW_OWNER` only checks the owner of views that are directly runtime-readable. A bypass-owned inner view in public, SELECT granted to the migrator, can be wrapped in a default owner-security outer view owned by that non-bypass migrator and granted only to the runtime. The inner is not a direct runtime endpoint and the outer owner is not bypassing; the bypassing inner still reads the rows. Recursive reachability alone does not establish safe execution semantics across the chain. Test this mixed-owner wrapper with a real own/foreign read control and reject the unsafe path while retaining the safe invoker control.

   Child safety is limited by `runtime_read_endpoints`, which collects SELECT only. A directly INSERT/UPDATE/DELETE-reachable descendant outside tenant_data can lack forced RLS/policies and remain absent from `UNSAFE_PARTITION_PATH`. Include effective write/column privileges and command-specific child protections, and test write-only cross-schema descendants. Resolve the already requested unsafe publication/access path rather than expanding into application business RBAC.

5. **HIGH — compare dedicated owner privileges at privilege/column granularity.** `owner_allowed_relations` records relation names, not allowed operations or columns. The later destructive/table-wide checks prohibit some broad privileges, but they do not reject every new column privilege on an already allowed table. For example a column UPDATE grant to the audit definer on its allowed audit_event relation is not DELETE/TRUNCATE/REFERENCES/TRIGGER and is not table-wide, so those conditions do not flag it. The accepted operator-definer validator does not validate the separate audit/void/admission owners on their behalf. Compare each dedicated owner's complete accepted table/column/sequence/function/schema/ownership profile, or reuse an equivalent accepted exact validator where available. Add same-relation wrong-operation and extra-column negatives, not only a new-relation grant. Preserve the now-correct NULL/default ACL resolution and installed operator protocol probes.
