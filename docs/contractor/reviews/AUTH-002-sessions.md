## Required corrections

1. **P1 — success transitions and audits are separate commits.** `server.mjs:31` uses independent `pool.query` calls; `routes.mjs:190–206` creates the session before inserting login_success, and lines 255–265 revoke before auditing logout. An audit error leaves a committed session/revocation behind while returning 503. The report's claim that failure prevents an unrecorded success is therefore insufficient: failure of the HTTP response does not undo the transition. Implement an explicit checked-out-client transaction shared by the transition and success audit; publish the cookie/receipt only after commit. Keep failed-login audit independently durable. Test injected audit failure and commit/rollback failures by checking actual stored state, not just response status. [node-postgres transactions](https://node-postgres.com/features/transactions) require one client for all transaction statements.

2. **P1 — rotation forks and expiration can be revived.** `session-store.mjs:206–254` SELECTs an unrevoked source, INSERTs a replacement and then revokes without a transaction, row lock or conditional-update result check. Concurrent rotations can both return live replacement tokens; failure after INSERT leaves both old and new sessions live. A rotation racing revoke can issue a replacement after logout. It also ignores idle expiry, so rotating an idle-expired session before its absolute deadline yields a valid new session. `refreshSession` likewise checks only revoked_at and can revive idle-expired rows. Make rotation/refresh validate expiry, user status and credential epoch at the mutation boundary; serialize source consumption and atomically create exactly one successor while preserving the absolute deadline. Add concurrent rotation/revoke and mid-operation failure tests. `routes.mjs:229` must not blanket-suppress refresh failures and return a stale success; report refreshed expiry from the validated operation.
