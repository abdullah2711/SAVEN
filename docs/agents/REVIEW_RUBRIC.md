# Review rubric

Version: 2. Created: 19 November 2026 (Asia/Karachi).
Source review base: `codex/pivot-003-rulings @ 27e91905a5271521b98328313265bd3cfaf03752`.
This v1 seeds rules from every review file present under docs/contractor/reviews at that SHA; references below identify the originating review families, including their correction/ACCEPT rounds. This is a review-history synthesis, not a current runtime inventory or a claim that all defects remain open. Principal decisions, scope amendments and later corrections govern over superseded findings; in particular D-018 preserves live legacy IAM flows and D-016 permits gaps but prohibits reuse. The source set has AUTH-006 through R4, not a separately named R5; do not invent a missing review.

## Maintenance and use

Read the current version as static context before each review; do not edit it during an in-flight review or contract execution. AFTER each review is committed, append one dated entry citing that review SHA, expressing any new defect pattern as the rule that would have caught it earlier, and bump the version. If no new pattern was caught, append that fact and the applicable existing rule IDs, and still bump the version. Preserve prior entries; superseding rules are appended with explicit references rather than silently rewriting history. Commit rubric maintenance outside all contractor TOUCH limits, without blocking in-flight work. Any repository-wide inventory made for a review records its own exact tree SHA and is re-based after tree-changing merges (D-017); this immutable historical source base is not a claim to inventory a later tree.

Tier derives mechanically from contract TOUCH at authoring; ambiguous work is Tier 1. Reviewer #2 never approves money/auth/schema/migration/audit/permission work, including tests of those boundaries. Follow SCALING_TRIGGERS.md for authority and onboarding; this rubric does not launch reviewers, change permissions or authorize merges. Treat applicability honestly: record NOT APPLICABLE with reasons instead of inventing coverage, and distinguish worker-reported results from reviewer execution.

## Rules seeded at version 1

### Scope, evidence and safe test infrastructure

- R01 — Review the exact base, implementation and delivery SHAs plus the combined delta against the actual contract; if a worktree is stale, inspect the requested immutable commit and disclose the mismatch rather than reviewing the wrong files. Sources: all review families; AUTH-009-R2.
- R02 — Enforce TOUCH and prerequisites without shrinking authorized purpose-map scope to example counts; schema placeholders do not prove operational features, and neither a disclosure nor a dispatcher relay can waive a required invariant. Sources: PIVOT-002 initial/b/c, PIVOT-003 technical rulings, PIVOT-004 initial, AUTH-009 initial/R1.
- R03 — Every DONE WHEN gate and explicitly required workflow needs exact tested-SHA evidence under the supported runtime; local focused passes do not substitute for a missing full-suite/CI result, and unsupported runtimes are not acceptance evidence. Sources: PIVOT-002/b/c; AUTH-001/R1; AUTH-008.
- R04 — Prove restricted behavior through separate actual runtime logins with no direct/transitive migrator/definer membership; SET ROLE from a privileged login and administrator-only positives do not establish the deployed boundary. Sources: PIVOT-002/b/c; PIVOT-004; PIVOT-005 initial/R2; AUTH-002, AUTH-003, AUTH-009 rounds.
- R05 — A disposable database does not isolate cluster roles: use an explicitly identified dedicated test cluster, namespaced owned objects and collision refusal before DDL; never borrow owner-server credentials or mutate pre-existing attributes/memberships. Sources: PIVOT-002/b/c, PIVOT-004-R1/R2.
- R06 — Execute the checked-in bootstrap rather than a fixture substitute; distinguish fixture collision safety from real install/reinstall safety, and prove fresh, compatible re-entry and incompatible-existing-state preservation. Sources: PIVOT-002b/c, AUTH-007-R2..R5.
- R07 — Cleanup only objects proven created by this run; preserve both primary and cleanup errors, retain TLS certificate verification and do not read/log credential files to prove metadata claims. Sources: PIVOT-002 initial/b/c, PIVOT-004-R1/R2, AUTH-001-R1.
- R08 — Preserve meaningful prior regression cases when extending tests; do not remove rollback/isolation/retention coverage or change general check/build dependencies outside explicit authorization. Sources: PIVOT-002b/c, PIVOT-005-R2/R3, AUTH-003-R2..R4.
- R09 — Every refusal test needs its specific error/constraint and a permitted positive control; prove setup succeeded, propagate unrelated exceptions, assert persisted postconditions, and do not let empty fixtures, an unrelated FK failure or a tautological assertion satisfy the property. Sources: AUTH-001/R1, PIVOT-004 initial, PIVOT-005 rounds, AUTH-003-R3/R4, AUTH-007-R3/R4.
- R10 — Fault injection must prove the intended statement/transaction phase was reached; distinguish reservation, authority, success and cleanup phases, and disclose before-execution versus real acknowledgement-loss injection. Sources: AUTH-003-R3/R4, AUTH-004-R1/R2, AUTH-007-R3..R5, AUTH-009-R3/R4.
- R11 — A mutation-proof claim requires the actual named test failing with the guard removed and passing after restoration; comments predicting failure or arithmetic about an old implementation are not execution evidence. Sources: AUTH-007-R3..R5, AUTH-009-R3/R4 evidence discipline.
- R12 — Review partial deliveries per finding as DONE/PARTIAL/UNTOUCHED with exact named tests, missing evidence and resolution owner; never convert a partial success into whole ACCEPT or assert absence of required behavior as proof. Sources: AUTH-009 initial/R1..R4, PIVOT-004 initial, PIVOT-005-R2.
- R13 — Correct scope contradictions on the record using source evidence and Principal authority; distinguish live legacy behavior from absent coverage in a new surface, assign future port ownership and preserve original events. Sources: AUTH-009-R1/R2 plus D-018 correction, PIVOT-003 technical rulings, PIVOT-002 ownership ruling.

### Schema, least privilege and installation

- R14 — PostgreSQL CHECK predicates must explicitly reject required NULL combinations; exercise invalid INSERT and UPDATE plus valid optional/encrypted controls, and validate additive constraints without rewriting history. Sources: AUTH-001/R1, AUTH-008.
- R15 — Preserve native relational financial invariants, not just individual field bounds; verify cross-field zero-quantity/value and other relationships against the actual source schema. Sources: PIVOT-003/R1.
- R16 — Canonical defaults and annotations must match exact reference seed values; growing configurable domains belong in effective-dated reference/config data, including nested JSON schemas rather than inline enums. Sources: PIVOT-003/R1, AUTH-009 initial/R1.
- R17 — Couple forced RLS and minimum per-table customer grants atomically; include required membership preselection isolation, exact text/UUID principal mapping and tenant/company parent constraints without exposing credentials or operator data. Sources: PIVOT-003 technical rulings; PIVOT-004 initial/R1/R2.
- R18 — Test permissive-policy widening against the actual granted role: restrictive guards must retain principal/tenant isolation even when an extra permissive policy ORs true; a role with no table grant is not a meaningful attack control. Sources: PIVOT-004-R1/R2; PIVOT-005 initial/R2.
- R19 — A SECURITY DEFINER runtime helper needs a dedicated constrained NOLOGIN owner, fixed search_path and exact least privileges; never execute it with the broad schema migrator's authority. Sources: PIVOT-004 initial, PIVOT-005 initial/R2, PIVOT-006 initial/R1.
- R20 — Validate pre-existing definer authority completely: flags, direct/transitive role paths, column/table/schema/function/default ACLs and ownership; refuse poisoned state without silently stripping unrelated grants, and test each privilege class. Sources: PIVOT-004-R1/R2; PIVOT-005 initial/R2; PIVOT-006 initial/R1.
- R21 — Append-only protection includes UPDATE, DELETE and statement-level TRUNCATE; issued entitlement claims are superseded by new versions, never rewritten, while owner guard-disabling power remains an explicit trust boundary. Sources: PIVOT-002/b/c; AUTH-001/R1; AUTH-009.
- R22 — Migration payloads own atomic installation and activation boundaries; preserve applied bytes and bindings, fail interrupted/conflicting installs without partial grants/exposure, and test retry/activation rather than only successful creation. Sources: AUTH-006-R3/R4; PIVOT-005 initial/R2/R3; PIVOT-006 initial..R3.
- R23 — Validate installed trigger/function contracts by exact table, event, timing, OID, arguments, predicate, firing mode, language/owner and fixed path, not names/counts alone; disabled or replica-only protections fail closed. Sources: AUTH-006-R3/R4; AUTH-007 inherited gate validation.

### Sessions, credentials and durable admission

- R24 — Success transition and success audit must commit together; failures must have independent observable durable evidence, and a returned credential must never imply success when the audit/commit boundary failed. Sources: AUTH-002 initial/R1/R2; AUTH-009 initial..R4.
- R25 — Every adapter/library path must enforce the same active principal, credential generation, realm, revocation, idle and absolute ceilings; refresh/update cannot revive an expired session, and list/count/bulk-token filters hash each token exactly once. Sources: AUTH-002 initial/R1/R2; AUTH-008 readiness boundary.
- R26 — Serialize session rotation/revocation and validate immutable configuration ceilings/effective dates; actual library composition and concurrent failure paths must be tested rather than assuming a first-party substitute is equivalent. Sources: AUTH-002 initial/R1/R2.
- R27 — Bound every KDF path, including dummy, verification, rehash and overload fallback; enforce absolute stored-parameter/input/salt/tag limits before native allocation and instrument concurrent work rather than measuring only nominal hash timing. Sources: AUTH-003 initial/R1/R2.
- R28 — Dummy work cannot authenticate: carry original-input validity separately, substitute bounded inputs only for workload, and unconditionally refuse missing/null/numeric/empty/oversize/NUL credentials even if the dummy verifier matches. Sources: AUTH-003-R1/R2.
- R29 — Non-enumeration covers malformed/unknown/compatibility verifier workload and provider-error behavior, not only equal JSON; bounded asynchronous mail handoff must not expose account existence through provider latency. Sources: AUTH-003 initial/R1; AUTH-005 initial/R2.
- R30 — Commit durable attempt reservation under serialized admission before KDF/provider work; exceptional paths must not escape budget accounting, and repeated accounting failure stops unaccounted work with an honest total-outage limit. Sources: AUTH-003 initial/R1/R2; AUTH-004-R1/R2; AUTH-005 initial/R2; AUTH-009.
- R31 — Use one canonical sanitized ingress identity for audit, limiter keys and all consumers; forwarded-address headers are default-off unless validated at the trusted boundary. Sources: AUTH-003 initial/R1/R2; AUTH-009 attribution checks.
- R32 — Throttle event time/order must be authoritative after lock acquisition with an unambiguous tie strategy; transaction-start timestamps or separate clocks cannot order delayed attempts safely. Sources: AUTH-003 initial/R1/R2; AUTH-005 initial/R2.
- R33 — Reuse the owned client for every nested auth lookup/mutation and prove size-one-pool progress; a second checkout while retaining the first is a deadlock/starvation defect. Sources: AUTH-003-R2/R3; AUTH-004 initial/R1; AUTH-005 initial/R2; AUTH-009-R3/R4.
- R34 — Guard uncertain BEGIN, COMMIT, ROLLBACK and partial lock acquisition/release; once uncertain, destroy that exact checkout, never clear its destruction flag after a successful unlock, and prove a clean subsequent borrower without claiming unknown commit rolled back. Sources: AUTH-003-R2..R4; AUTH-002-R2; AUTH-009-R3/R4.
- R35 — A reset/verification token binds immutable subject, purpose, current address and credential generation at consume time; timestamps cannot substitute for generation, and atomic single use/revoke-all must survive races and replay. Sources: AUTH-005 initial/R2; AUTH-008; AUTH-009 reset events.
- R36 — All credential/token/session display remains digest-only; protected HttpOnly cookie transport is not permission to serialize a raw session bearer in list/API/UI output. Sources: AUTH-002-R2 owner follow-up/D-012, AUTH-009 secret assertions.

### MFA, tenant and operator authority

- R37 — Password-only enrollment cannot replace an existing verified factor; replacement/disable require current reauthentication and existing-factor proof, while recovery/enrollment retries have durable admission before any KDF/factor work. Sources: AUTH-004 initial/R1/R2.
- R38 — MFA authority reads must bind the verified transaction-local principal under accepted RLS and fail closed if unresolved; an empty result caused by missing context is not evidence MFA is unnecessary. Sources: AUTH-004 initial/R1; AUTH-006 initial; AUTH-009-R1..R4.
- R39 — Serialize factor lifecycle and invalidate other sessions' assurance on replacement/disable; validate encryption/recovery key versions, entropy and sizes, and prove replay/single-use behavior across sessions. Sources: AUTH-004 initial/R1/R2.
- R40 — A valid pre-read session is not mutation authority: revalidate active principal, realm, expiry, epoch and current required MFA/session/factor assurance after blocking locks inside the owned transaction. Sources: AUTH-004-R1/R2; AUTH-006 initial..R4; AUTH-007-R1/R2; AUTH-009-R1..R4.
- R41 — Tenant selection and business admission share reserved authority through business COMMIT on the owned business client; enforce required MFA/realm in the reusable gate, exact current selected role/epoch and company/resource scope, not optional caller checks. Sources: AUTH-006 initial/R1/R2.
- R42 — A last-minute reread does not serialize authority: cooperating writers, including new membership associations and role requires_mfa changes, must take the exclusive gate against shared admitted work held through commit. Sources: AUTH-006-R1..R4; AUTH-009-R1..R4.
- R43 — Acquire the common authority gate before user/factor/session/table locks, including installer DDL; sample trusted time after waits and test invalidation-first and mutation-first with observable lock waits and positive controls. Sources: AUTH-006-R2..R4; AUTH-007-R1/R2/R4/R5; AUTH-009-R3/R4.
- R44 — An operator MFA label must come from verified issuer AMR semantics or a reviewed equivalent predicate; a lone OTP/hardware/software method and a weaker configured policy cannot satisfy mandatory multi-factor assurance. Sources: AUTH-007 initial/R1.
- R45 — Bind operator sessions to verified issuer/subject/audience, current mapping incarnation/role/assurance and source freshness; reserve that authority at exchange and revalidate it for every later privileged transaction, without universal support access. Sources: AUTH-007 initial/R1/R2/R5.
- R46 — Replay identity derives from canonical verified encoding/claims, not alternate raw bearer spellings; enforce JOSE base64url canonicality, source expiry/max age and finite iat after owned-boundary waits. Sources: AUTH-007 initial/R1/R2.
- R47 — Publish refresh single-flight state before invoking callbacks; coalesce concurrent unknown-key refreshes, retain known-good keys on failure, respect cooldown, and recover from synchronous throws as well as rejected promises. Sources: AUTH-007 initial/R1/R2.
- R48 — Mapping incarnations and all allocators are advance-only across delete/recreate, failed reinstall and restore; reconcile retained binding-only high-water evidence as well as live rows and never reuse explainable gaps. Sources: AUTH-007-R1..R5; D-016.
- R49 — Validate allocator increment, cycle, cache, bounds, type and ownership before reconciliation; test genuinely forced advancement, already-ahead state, interruption after the real adjustment and overflow refusal with exact bigint comparisons. Sources: AUTH-007-R2..R5.

### Accounting, audit and recovery

- R50 — Active GL includes only physically posted, effectively non-voided entries; terminal void retains original sources/effects/evidence, excludes the original once, remains absolutely immutable and does not double-adjust with an active opposite entry. Sources: PIVOT-005 initial..R5, D-013/D-014.
- R51 — Read/delete/approval authority uses canonical permissions and current actor/resource/company/branch/account/amount restrictions, not invented JSON shapes or business-role names; read visibility remains role-agnostic at the DB layer under D-014. Sources: PIVOT-005 initial/R2/R3/R4.
- R52 — Approval metadata alone is not independent authorization: bind an actor-authorized transition to the exact immutable submission/digest/payload, reject self/fabricated/stale approvals and preserve decisions when permissions/policy change. Sources: PIVOT-005-R2/R3/R4.
- R53 — Resolve policy versions within each policy identity, apply role/global applicability deliberately, combine applicable independent keys conservatively and bind all contributing identities/versions; a larger version on another key is not priority. Sources: PIVOT-005-R3/R4/R5.
- R54 — Protect both ends of correction/dependency links and their valid creation timing; serialize writers with post/void and recheck commit-time invariants, including late-child races and terminal reversal links. Sources: PIVOT-005 initial/R2/R3.
- R55 — Same-key replay returns a retained receipt without new effects; same-key/different-content or entry conflicts have an explicit contract under concurrency, not an accidental UNIQUE error. Sources: PIVOT-005 initial/R2/R3.
- R56 — Balanced journals plus existence of movements do not establish financial reconciliation: independently prove exact supported trade/stock/source effects or explicitly refuse unsupported shapes before POSTED. Sources: PIVOT-005 initial/R2/R3.
- R57 — Audit actor/provenance comes from verified context and declared trusted origin, never arbitrary native-audit actor input or fabricated human origin; preserve native/business/auth/operator streams independently. Sources: PIVOT-006 initial/R1..R3; AUTH-009 rounds.
- R58 — Before/after serialization needs a versioned schema-aware secret boundary, not whole-row copying or a global column-name allow-list; unknown columns/types fail closed and all registered tables need inventory/activation coverage. Sources: PIVOT-006 initial/R1/R2/R3.
- R59 — Serializer classification/fingerprints use actual catalog type/base identity and effective typmod, not unqualified typname; exercise precision-qualified decimals, domain-over-decimal money and domain-over-text redaction. Sources: PIVOT-006-R1/R2/R3.
- R60 — Audit event configuration is external, validated and versioned at the writer boundary; required-event traceability is independent of the catalog, and real available producer paths—not event-name loops—prove coverage. Sources: AUTH-009 initial/R1..R4, D-018 narrowing.
- R61 — Cover early origin/realm/session/CSRF/assurance refusals as well as route-body failures, with once-only independent evidence and unknown attribution until authority is verified; preserve durable reservation counting without duplicate safety-net rows. Sources: AUTH-007 initial/R1 guard limit, AUTH-009 initial..R4.
- R62 — Recovery instructions must match actual backup format, verification tool, recovery signal, output destination and supported target/timeline semantics; a template is not an executed drill or an operationally installed archive tool. Sources: PIVOT-011 initial/R1/R2/R3.
- R63 — Fence restored data, WAL, tablespaces, symlinks, config, credentials, replication and archive publication before startup; isolated ports alone do not isolate source paths or prevent inherited writes. Sources: PIVOT-011 initial/R1.
- R64 — Archive publication requires remote atomic no-replace semantics, verified identical retry and explicit conflict refusal; fence the source and record a reachable unique post-backup restore point with a pinned timeline before claiming comparison equivalence. Sources: PIVOT-011 initial/R1/R2/R3.
- R65 — Recovery comparison covers every authoritative persisted column/table including leases, outbox identity, provenance and security state; anchor expected tenants, compare complete-row digests under one consistent pinned snapshot, and hash secrets internally without exporting them. Sources: PIVOT-011 initial/R1/R2/R3.
- R66 — Export/digest pipelines fail closed on SQL error, missing table, interrupted/empty stream or manifest drift; verify completion, counts and non-vacuous controls rather than accepting two matching empty hashes. Sources: PIVOT-011-R1/R2/R3.
- R67 — Every recovery integrity check states the failure action and notification owner; retain the write fence and mark an unknown corrective procedure MISSING instead of inventing repair, and never renumber/reuse identities during recovery. Sources: PIVOT-011 recovery gates and subsequent Principal remediation/D-016 directives.
