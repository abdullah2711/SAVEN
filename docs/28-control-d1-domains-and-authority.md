# D1 control aggregates and authority contract

Target logical aggregates: identity (users, sessions, tenant membership, ultimate owner, revocation epoch); commerce (applications, billing, payment review, subscription ledger); fleet (node identity, tenant placement, generation, provisioning/migration/backup jobs). AI reservations use a separately measured coordinator when needed. These are boundaries, not a claim that D1 databases have been provisioned. Private-local uses equivalent native SQLite stores and conformance cases.

Each aggregate owns its audit/outbox and idempotency in the same transaction. D1 batch is atomic only within its bound database. Activation is a durable saga: RECEIVED → REVIEWED → PAYMENT_VERIFIED → PROVISIONING → TENANT_READY → MEMBERSHIP_READY → ACTIVE; failures stay retryable or NEEDS_OPERATOR. No intermediate commerce approval can authorize business posting. Unique tenant/request IDs deduplicate concurrent approvals. An owning-domain outbox precedes export to independent audit storage.

Gateway verifies session, active tenant, company membership and entitlement, then issues a short-lived signed assertion: installation, tenant, company, actor, session, command, audience/node, ownerGeneration, membershipEpoch, entitlementVersion, issued/expiry, nonce, requestDigest and correlationId. The node verifies signature, audience, replay, generation, current epochs and local grants/resources/workflow before one local commit. Browser role/tenant strings are never trusted authority. Expiry durations and outage leases are unresolved evidence/policy decisions; sensitive admin and rights changes fail closed. No lease window is silently assumed.

Tenant SQLite owns business roles, resource/column predicates, approvals and permission history. An explicit deny wins in the proposed policy contract; a simulator must explain all intersected grants, entitlements and denials. Cached reads/BI/jobs/exports include scope version and reauthorize on execution. Global identity is not a business-wide role. Operator support uses attributed case-bound delegation, MFA and separate audit, never recoverable passwords.

Required tests: same-user different-tenant roles; stale/revoked assertions; forged actor/company; route generation race; expired nonce; resource denial in aggregates/search/export; identity outage; delayed commerce/fleet saga; duplicate activation; domain-local rollback; D1/native control-store equivalence. Current PG auth remains in place until these contracts are proved.
